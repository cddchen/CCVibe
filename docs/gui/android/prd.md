# CCLink Android App 功能 PRD

## 1. 文档目的

本文档描述 CCLink Android App 首个完整版本的功能要求，供产品、设计、Android 开发、daemon 开发和测试共同使用。

Android App 通过 WebSocket 连接运行在 Mac 或其他主机上的 `cc-agent-daemon`，用于浏览 Claude 历史会话、新建会话、继续历史会话，以及查看和控制正在运行的模型任务。

## 2. 产品目标

1. 用户可以在 Android 手机上连接指定的 CCLink daemon。
2. 用户可以按工作目录查看历史会话和运行中的会话。
3. 用户可以新建会话、继续历史会话，并接收实时流式回复。
4. App 退出会话页、进入后台或短暂断网时，不主动停止 daemon 中的对话。
5. 用户重新进入会话后，可以继续查看进度、停止任务或发送下一条消息。
6. Android 端的核心功能和 Mac、Web 端保持一致，并针对移动端进行布局和交互适配。

## 3. 本期功能范围

本期包含：

- daemon 登录、连接校验和凭据保存。
- App 启动时自动连接。
- 断线自动重连和手动断开连接。
- 工作目录信任和添加。
- 按工作目录分组展示会话。
- 新建会话、加载历史会话和继续会话。
- 实时流式消息、Markdown、thinking 和工具调用展示。
- 模型、思考强度和权限模式切换。
- 工具权限确认和 AskUserQuestion 问题回答。
- 发送消息、停止运行和异常恢复。
- Android 前后台切换后的会话恢复。
- 深色、浅色和跟随系统主题。

本期不包含：

- 图片、文件和相机附件发送。
- 语音输入和语音播放。
- 工具级“重新执行”或“继续执行”按钮。
- 会话分享、导出和多端同步编辑。
- 会话置顶、归档、删除和批量管理。
- Android 本地运行 Claude 或 daemon。

参考图中的附件图标、工具重试按钮等不在本期实现范围内，不应作为可点击功能展示。

## 4. 整体页面结构

App 包含以下三个主要页面：

1. 登录连接页。
2. 会话列表页。
3. 会话详情页。

页面流程：

```text
启动 App
  ├─ 未保存连接信息 → 登录连接页
  └─ 已保存连接信息 → 自动连接
       ├─ 成功 → 会话列表页
       └─ 失败 → 登录连接页并显示失败原因

会话列表页
  ├─ 点击目录内“新建会话” → 新会话详情页
  └─ 点击历史会话 → 历史会话详情页

会话详情页
  ├─ 会话仍在 daemon 中运行 → 挂接实时会话
  └─ 会话不在运行 → 展示历史，下一次发送时恢复会话
```

## 5. 登录与连接

### 5.1 登录页内容

登录页包含：

- 主机或链接输入框。
- 端口输入框，默认值为 `4733`。
- TLS 开关，用于选择 `ws://` 或 `wss://`。
- Token 输入框。
- Token 显示/隐藏按钮。
- 登录按钮。
- 连接状态和错误信息。

主机输入框支持以下格式：

- IP 地址，例如 `192.168.1.10`。
- 域名，例如 `mac.example.com`。
- 完整 WebSocket 地址，例如 `ws://192.168.1.10:4733`。
- 完整安全 WebSocket 地址，例如 `wss://mac.example.com/ws`。

当用户输入完整 WebSocket 地址时，App 自动解析协议、主机、端口和路径；端口输入框仅在地址中未包含端口时生效。

### 5.2 登录校验

点击登录后按以下顺序处理：

1. 校验主机、端口和 Token 不为空且格式合法。
2. 建立 WebSocket 连接。
3. 调用 `auth` 校验 Token。
4. 调用 `ping` 确认 daemon 可正常响应。
5. 校验成功后保存连接配置并进入会话列表页。

登录期间：

- 登录按钮显示加载状态且不可重复点击。
- 输入区域保持当前内容。
- 连接成功前不得进入会话列表页。

连接失败时需要区分并展示：

- 地址或端口格式错误。
- 网络不可达。
- 连接超时。
- TLS 或证书错误。
- Token 错误。
- daemon 返回的其他错误。

### 5.3 凭据保存

- Token 必须使用 Android Keystore 支持的安全存储方案保存。
- 主机、端口、TLS 开关和 WebSocket 路径可以使用本地偏好设置保存。
- 不得在日志、错误上报或普通明文配置文件中输出完整 Token。
- 主动断开连接时保留连接配置，方便用户重新连接。

### 5.4 启动自动连接

App 启动时：

- 如果没有保存完整连接信息，直接展示登录页。
- 如果已保存连接信息，先展示“正在连接”状态并自动尝试连接。
- 自动连接成功后直接进入会话列表页。
- 自动连接失败后进入登录页，自动填充已保存内容并展示失败原因。
- 自动连接失败不得清空已保存的配置和 Token。

### 5.5 断线重连

非用户主动断开的情况下，WebSocket 断开后自动重连：

- 使用指数退避策略。
- 建议间隔为 1 秒、2 秒、4 秒、8 秒、16 秒，最大 30 秒。
- 重连期间页面保留当前内容，并展示“连接已断开，正在重连”。
- 重连成功后自动刷新会话状态，并恢复当前会话的历史和实时挂接。
- 重连失败期间禁止发送消息、停止任务和提交权限决定。

### 5.6 手动断开

会话列表页右上角提供设置按钮。点击后弹出设置面板，至少包含：

- 当前连接地址。
- 当前连接状态。
- 断开连接按钮。

点击断开连接后：

- 关闭 WebSocket。
- 停止自动重连。
- 返回登录页。
- 保留已保存的连接配置。
- 不主动停止 daemon 中正在运行的会话。

## 6. 会话列表页

### 6.1 页面结构

页面顶部包含：

- 页面标题。
- daemon 连接状态。
- 手动刷新按钮。
- 添加工作目录按钮。
- 设置按钮。

主体区域按工作目录分组展示会话。

### 6.2 数据加载

进入页面后：

1. 调用 `history.listAllLocal` 获取 daemon 主机上的本地历史项目。
2. 调用 `workspace.list` 获取手动添加和信任的工作目录。
3. 合并相同路径的目录。
4. 必要时调用 `history.listSessions` 补充目录中的历史会话。
5. 调用 `session.listActive` 获取当前活跃会话状态。

页面支持下拉刷新和顶部刷新按钮。刷新时不得清空旧列表，加载成功后再替换数据。

### 6.3 目录分组

每个目录分组展示：

- 目录名称，默认使用路径最后一级名称。
- 完整目录路径，过长时中间截断。
- 目录内会话数量。
- 目录最近更新时间。
- 是否存在运行中的会话。
- 展开或折叠按钮。
- 新建会话按钮。

目录展开状态需要在本地持久化。

手动添加但暂时没有历史会话的目录也需要展示，并允许新建会话。

### 6.4 排序规则

目录内会话排序：

1. 按会话 `lastTimestamp` 从新到旧排序。
2. 时间相同时按 sessionId 升序，保证列表顺序稳定。

目录排序：

1. 取目录内最新会话的 `lastTimestamp` 作为目录更新时间。
2. 按目录更新时间从新到旧排序。
3. 空目录使用工作目录创建时间参与排序。
4. 时间相同时按完整目录路径升序排序。

### 6.5 会话行

每个会话至少展示：

- 会话标题。
- 消息数量。
- 最近更新时间。
- 运行状态。
- sessionId 缩略值。

会话标题优先级：

1. 用户设置的会话名称。
2. 第一条用户消息的单行摘要。
3. `会话 + sessionId 前 8 位`。

如果现有历史列表接口没有返回标题信息，需要扩展 daemon 的历史会话摘要数据。

运行状态包括：

- 启动中。
- 运行中。
- 可挂接。
- 已完成。
- 已中断。
- 失败。

活跃状态通过 `session.listActive` 定时刷新，建议前台每 8 秒刷新一次。

### 6.6 新建会话

每个目录分组内提供明显的“新建会话”按钮。

点击后进入空白会话详情页，但不立即创建 daemon session。用户发送第一条消息时再调用 `session.create`，避免产生空会话。

### 6.7 添加和信任工作目录

点击添加工作目录后弹出输入框，用户输入 daemon 主机上的绝对路径。

提交后调用 `workspace.add`：

- 添加成功后刷新列表。
- 路径不存在或不是目录时展示错误。
- 重复添加时不创建重复目录。
- Android 端不提供远程文件选择器，用户需要手动输入 daemon 主机上的路径。

### 6.8 页面状态

页面需要覆盖：

- 首次加载状态。
- 刷新状态。
- 空列表状态。
- 部分目录加载失败状态。
- 连接断开状态。
- 全部加载失败状态和重试按钮。

## 7. 会话详情页

### 7.1 页面头部

页面头部包含：

- 返回按钮。
- 会话标题。
- 工作目录名称或路径。
- 当前运行状态。
- 更多设置按钮。

新会话在创建前标题显示“新会话”。创建成功后更新为正式会话标题。

### 7.2 工作目录信任检查

进入会话详情页后调用 `workspace.checkTrust`。

如果目录未信任，展示弹窗：

- 信任当前目录。
- 信任父目录。
- 取消并返回会话列表。

用户确认后调用 `workspace.add`。未完成信任前：

- 不加载历史消息。
- 不创建或恢复会话。
- 不允许发送消息。

### 7.3 打开历史会话

打开历史会话时：

1. 调用 `history.loadSession` 加载完整历史。
2. 将历史事件转换为用户消息、Assistant 消息、thinking 和工具调用卡片。
3. 调用 `session.attachIfLive` 检查该会话是否仍在 daemon 中运行。
4. 如果仍在运行，挂接会话并继续接收实时事件。
5. 如果不在运行，正常展示历史，用户下一次发送时再恢复会话。

历史加载失败时保留页面并提供重试按钮。

### 7.4 恢复历史会话

用户在历史会话中发送新消息时：

- 优先尝试使用当前活跃 session。
- 活跃 session 不存在时调用 `session.resume`。
- resume 成功后调用 `session.attach`。
- 再调用 `session.sendMessage` 发送消息。
- resume 使用当前选择的模型、思考强度和权限模式。

如果 daemon 已重启，只要历史文件仍存在，就应通过 resume 继续该会话。

### 7.5 新建会话

新会话发送第一条消息时：

1. 调用 `session.create`，传入工作目录、模型、思考强度和权限模式。
2. 获取 runtime sessionId 后立即挂接。
3. 发送用户消息。
4. 收到 SDK 正式 sessionId 后更新当前会话标识。
5. 后续事件需要同时识别 runtimeId 和正式 sessionId，避免丢失事件。

创建或发送失败时：

- 保留用户输入的消息内容。
- 将本轮标记为失败。
- 提供再次发送入口。
- 不得重复创建多条相同的用户消息。

## 8. 消息展示

### 8.1 用户消息

- 使用独立气泡展示。
- 保留换行。
- 长文本自动换行。
- 支持选择和复制文本。

### 8.2 Assistant 消息

Assistant 消息支持 Markdown 和 GFM，至少包括：

- 标题和段落。
- 有序和无序列表。
- 粗体、斜体和删除线。
- 引用。
- 行内代码和代码块。
- 表格。
- 链接。
- Markdown 图片展示。

代码块和表格内容超出屏幕宽度时横向滚动，不得撑破页面。

外部链接点击后交给系统浏览器打开。

### 8.3 流式回复

- 收到增量事件后实时更新当前 Assistant 消息。
- 流式过程中显示思考中或生成中状态。
- 显示当前模型名称、运行耗时和 token 使用量；无数据时不展示占位值。
- 收到 result 或终止状态后结束流式状态。
- 收到错误时保留已生成内容并展示错误信息。

### 8.4 Thinking

- thinking 使用独立的可折叠区域展示。
- 流式阶段默认展开。
- 回复完成后默认折叠。
- 用户可以手动展开或收起。

### 8.5 工具调用

工具调用使用卡片展示，UI 风格参考提供的 Android 图片。

卡片至少展示：

- 工具名称。
- 工具输入摘要。
- 执行状态。
- 成功或失败标识。
- 展开或折叠按钮。

展开后展示：

- 完整工具输入 JSON。
- 工具执行结果。
- 错误内容。

工具状态包括：

- 等待权限。
- 执行中。
- 成功。
- 失败。
- 已拒绝。

连续的多个工具调用可以在视觉上分组展示，但每个工具仍需保留独立状态。

本期只负责展示状态，不提供工具级重试和继续执行功能。

### 8.6 历史消息过滤

以下内部记录不得作为普通聊天消息展示：

- compact summary。
- transcript-only 消息。
- compact boundary。
- 仅包含 tool result 的内部用户消息。
- SDK 初始化和内部系统事件。

工具结果需要合并回对应的工具调用卡片。

### 8.7 长会话性能

- 消息列表使用懒加载列表实现。
- 历史消息和流式更新不得导致整个列表频繁重绘。
- 默认自动跟随最新回复。
- 用户主动向上滚动后暂停自动跟随，并展示“回到最新消息”按钮。
- 点击按钮后滚动到底部并恢复自动跟随。

## 9. 消息输入区

### 9.1 布局

输入区固定在页面底部，样式参考提供的 Android 图片，包含：

- 文本输入框。
- 模型选择入口。
- 思考强度选择入口。
- 权限模式入口。
- 发送或停止按钮。

本期不展示附件按钮。

### 9.2 输入框

- 默认高度为 1 行。
- 根据内容自动增长。
- 最多显示 3 行。
- 超过 3 行后输入框内部滚动。
- 支持中文输入法组合输入，不得在拼音确认前误发送。
- 空白消息不可发送。
- 发送时去除首尾无意义空白，但保留正文换行。

实体键盘交互：

- Enter 发送。
- Shift + Enter 换行。

### 9.3 模型选择

点击模型名称后展示底部浮层，包含：

- Opus。
- Sonnet。
- Haiku。

模型对应的实际模型 ID 通过 `settings.get` 获取；服务端未配置时使用客户端默认 ID。

模型切换规则：

- 新会话使用当前选择的模型创建。
- 历史会话使用当前选择的模型 resume。
- 会话正在运行时禁止切换。
- 切换结果在下一轮对话生效。

### 9.4 思考强度

点击思考强度后展示底部浮层，包含：

- low：低。
- medium：中。
- high：高。
- xhigh：极高。
- max：最高。

默认值优先使用 `settings.get` 返回的设置，否则使用 high。

会话运行时禁止切换，切换结果在下一轮对话生效。

### 9.5 权限模式

权限模式可以放在输入区二级菜单或会话更多设置中，包含：

- default。
- acceptEdits。
- plan。
- auto。
- bypassPermissions。
- dontAsk。

新建或恢复会话时传入当前权限模式。

活跃会话切换权限模式时调用 `session.setPermissionMode`。`bypassPermissions` 需要明显风险提示。

### 9.6 发送和停止

空闲状态：

- 右侧展示发送按钮。
- 输入不为空且连接正常时可点击。

运行状态：

- 发送按钮切换为停止按钮。
- 禁止重复发送新消息。
- 点击停止后调用 `session.interrupt`。
- 停止成功后保留已生成内容，并将状态显示为“已停止”。
- 停止后允许继续发送下一条消息。

## 10. 工具权限与问题交互

### 10.1 普通工具权限

收到 `permission/request` 后展示权限确认弹窗或底部面板，包含：

- 工具名称。
- 工具输入内容。
- 允许按钮。
- 拒绝按钮。
- 可选的拒绝原因。

允许时可以编辑提交给工具的 JSON 输入。提交前必须校验为合法 JSON object。

提交后调用 `permission.respond`。

### 10.2 AskUserQuestion

当工具名称为 `AskUserQuestion` 时使用专门的问题面板：

- 展示问题标题和说明。
- 支持单选。
- 支持多选。
- 支持多个连续问题。
- 必填问题未完成前不可提交。
- 用户取消时按拒绝处理。

提交时将答案写入 `updatedInput.answers`，并调用 `permission.respond`。

### 10.3 安全要求

- App 不得自动允许工具权限。
- 权限请求超时或连接断开时按拒绝处理。
- 已过期请求不得再次提交。
- 重新连接并挂接会话后，后续权限请求必须绑定到当前 Android 连接。
- daemon 需要支持活跃会话权限接收方随重新挂接更新，不能继续发送给已经断开的旧连接。

## 11. App 前后台与会话恢复

### 11.1 进入后台

App 进入后台时：

- 不调用 `session.interrupt`。
- 不调用 `session.delete`。
- 不主动停止 daemon runner。
- WebSocket 是否保持由系统网络和进程状态决定。

对于不需要人工授权的模型输出和工具调用，daemon 可以继续执行。

如果后台期间出现需要人工确认的权限请求：

- 连接仍可用时可以发送系统通知，点击后进入对应会话。
- 连接已断开时不得自动允许，按 daemon 安全策略拒绝或超时。

### 11.2 回到前台

App 回到前台时：

1. 检查 WebSocket 状态。
2. 必要时自动重连。
3. 刷新 `session.listActive`。
4. 当前页面为会话详情时重新加载最新历史。
5. 调用 `session.attachIfLive` 重新挂接。
6. 合并历史和实时事件，避免重复消息。

### 11.3 App 进程被系统回收

App 重新启动后：

- 使用保存的连接信息自动连接。
- 进入会话列表后展示 daemon 中仍活跃的会话。
- 用户打开活跃会话时重新挂接。
- 用户打开已完成会话时加载完整历史。
- daemon 活跃 runner 不存在时，下一次发送使用 `session.resume`。

### 11.4 切换会话

- 从一个运行中的会话返回列表或进入另一个会话时，不停止原会话。
- 可以对原会话调用 `session.detach`，仅取消当前页面订阅。
- 会话列表继续展示其运行状态。
- 再次进入时调用 `session.attachIfLive`。

### 12.1 主题

## 13. 错误处理

所有错误都需要转换为用户可理解的提示，不直接展示原始堆栈。

主要错误场景：

- 登录和 Token 校验失败。
- daemon 不可达。
- WebSocket 中断。
- 工作目录不存在或未信任。
- 历史会话不存在。
- session 已失效。
- session create、resume、send 或 interrupt 失败。
- Markdown 或历史记录中存在异常数据。
- 权限请求已过期。

错误提示不能覆盖已加载的聊天内容。可恢复错误需要提供重试入口。

- 历史会话摘要返回可展示的会话标题，或返回生成标题所需的信息。
- 重新挂接活跃会话后，将后续权限请求的接收方更新为当前连接。

## 15. 验收标准

### 15.1 登录连接

- 能输入主机、端口、TLS 和 Token 并成功连接。
- Token 错误、网络失败和超时能展示明确错误。
- 登录成功后安全保存配置。
- App 再次启动时能自动尝试连接。
- 自动连接失败时返回登录页并保留配置。
- 断线后能自动重连。
- 手动断开后停止重连并返回登录页。

### 15.2 会话列表

- 能展示 daemon 主机上的历史会话。
- 会话按工作目录分组。
- 目录内会话按更新时间倒序。
- 目录按目录内最新会话时间倒序。
- 能展开和折叠目录并记住状态。
- 能添加工作目录。
- 每个目录能够新建会话。
- 能展示运行中或可挂接状态。

### 15.3 会话详情

- 能打开历史会话并展示完整有效消息。
- 能在未信任目录进入前完成信任确认。
- 能挂接仍在运行的会话。
- 能恢复已结束或 daemon 重启后的历史会话。
- 新会话第一条消息发送时正确创建 session。
- 能发送消息并接收实时流式回复。
- 能停止运行中的回复。

### 15.4 消息渲染

- 用户消息和 Assistant 消息样式明确区分。
- Markdown、代码块、表格、链接和图片正常展示。
- thinking 可以展开和折叠。
- 工具调用能够展示输入、结果和状态。
- 历史消息和实时消息样式一致。
- 内部 compact 和纯工具结果记录不会被错误展示。
- 长会话滚动和流式更新无明显卡顿。

### 15.5 输入和模型设置

- 输入框可以从 1 行增长到 3 行，超出后内部滚动。
- 空消息不能发送。
- 运行时发送按钮切换为停止按钮。
- 能切换 Opus、Sonnet 和 Haiku。
- 能切换 low、medium、high、xhigh 和 max。
- 能切换权限模式。
- 运行中不能错误切换模型和思考强度。

### 15.6 权限交互

- 普通工具权限可以允许或拒绝。
- 可以查看并编辑允许时的工具输入。
- AskUserQuestion 可以完成单选、多选和提交。
- 断开连接后不得自动允许权限。
- 重新挂接后新的权限请求能够发送给当前 Android 客户端。

### 15.7 后台恢复

- App 返回列表或进入后台时不会停止运行中的 daemon 会话。
- 回到前台后能刷新历史并重新挂接。
- App 进程被回收后重新启动，仍能发现 daemon 中的活跃会话。
- daemon runner 丢失时能够通过历史 sessionId resume 后继续对话。
